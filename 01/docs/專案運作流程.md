# 專案運作流程說明

本文件說明整個專案從「原始碼 → 建置 → 執行 → 測試」的完整脈絡，以及三個角色（C 核心、Python 包裝、測試）如何協同運作。

---

專案的核心思想：

> **C 負責「跑得快」**（socket + 網路），**Python 負責「好用」**（簡單 API），**build.sh 負責串起來**，**測試負責把關**。

## 2. 三個角色的分工

| 角色 | 檔案 | 職責 |
|------|------|------|
| **C 核心** | `src/curl.c` | 直接處理 DNS、TCP、HTTP/HTTPS(TLS) 協定，效能最高 |
| **Python 包裝** | `src/curl.py` | 用 ctypes 呼叫 C，提供 `fetch()` / `fetch_text()` / `fetch_json()` |
| **建置腳本** | `build.sh` | 自動編譯 C，產出函式庫與可執行檔 |
| **測試** | `tests/` | 驗證 C 與 Python 兩層都正常 |

呼叫層級：

```
[你的程式]
    │  呼叫
    ▼
[curl.py]  ← Python API 層
    │  ctypes.CDLL + call http_get()
    ▼
[libcurl_wrapper.so]  ← C 函式庫層
    │  http_get()
    ▼
[src/curl.c]  ← 核心邏輯：socket / HTTP / HTTPS(TLS)
    │  http → send() / recv()
    │  https → SSL_connect / SSL_write / SSL_read
    ▼
[網路 / https://httpbin.org]
```

## 3. 建置流程（build.sh）

```
./build.sh
```

```
1. 檢查環境        gcc 存在？
      │
      ▼
2. 建目錄         mkdir -p build
      │
      ▼
3. 編譯目的檔     gcc -O2 -Wall -Wextra -c src/curl.c → build/curl.o
      │
      ▼
4. 打包靜態庫     ar rcs libcurl_wrapper.a curl.o
      │
      ▼
5. 編譯共用庫     gcc -fPIC -shared curl.c -lssl -lcrypto → libcurl_wrapper.so
      │
      ▼
6. 編譯可執行檔   gcc -DBUILD_STANDALONE curl.c -lssl -lcrypto → build/curl
      │
      ▼
7. 完成           印出產物清單
```

對應的 build.sh 內容：

```bash
#!/bin/bash
set -e                                              # 任一指令失敗立即停止

CC="${CC:-gcc}"                                     # 可用 CC=clang 覆寫
CFLAGS="${CFLAGS:--O2 -Wall -Wextra}"               # -O2 最佳化、開警告
LDFLAGS="${LDFLAGS:--lssl -lcrypto}"                # 連結 OpenSSL（HTTPS 用）
BUILD_DIR="build"
SRC_DIR="src"

mkdir -p "$BUILD_DIR"

# 4. 靜態函式庫（給 C 程式連結用）
$CC $CFLAGS -c "$SRC_DIR/curl.c" -o "$BUILD_DIR/curl.o"
ar rcs "$BUILD_DIR/libcurl_wrapper.a" "$BUILD_DIR/curl.o"

# 5. 共用函式庫（給 Python ctypes 動態載入用）
$CC $CFLAGS -shared -fPIC "$SRC_DIR/curl.c" -o "$BUILD_DIR/libcurl_wrapper.so" $LDFLAGS

# 6. 獨立執行檔（手動測試用）
$CC $CFLAGS "$SRC_DIR/curl.c" -o "$BUILD_DIR/curl" -DBUILD_STANDALONE $LDFLAGS
```

### 為什麼同一份 curl.c 可以編出三種東西？

靠 `#ifdef BUILD_STANDALONE`：

- 編函式庫：機器碼裡 **沒有** main()，只輸出 `http_get()` 符號。
- 編執行檔：加上 `-DBUILD_STANDALONE`，多含一個 `main()`。

| 產物 | 用途 | Python 用的是哪個？ |
|------|------|---------------------|
| `libcurl_wrapper.a` | 靜態連結給 C 程式 | ✗ |
| `libcurl_wrapper.so` | 動態載入給 Python ctypes | ✓ |
| `curl` | 命令列手動測試 | ✗ |

## 4. 執行流程

### 情境 A：命令列（手動測試）

```bash
./build/curl http://httpbin.org/get
```

1. `main()` 收 `argv[1]` = URL
2. 呼叫 `http_get(url, &status_code)`
3. 印出 `Status: 200` 與 body
4. `free()` 釋放記憶體後結束

### 情境 B：Python 程式（一般使用）

```python
from curl import fetch, fetch_json

result = fetch("http://httpbin.org/get")        # 回傳 dict
data    = fetch_json("http://api.example.com")  # 直接拿 JSON
```

`curl.py` 內部動作：

```
fetch(url)
  └─ with MiniCurl() as client:
        try: 載入 build/libcurl_wrapper.so  ← ctypes.CDLL()
             │  成功 → 用 _NativeBackend
             │
             └─ 失敗(OSError) → 印 Warning
                     │
                     ▼
                用 _PythonBackend（urllib 純 Python）
```

- **WSL / Linux**：成功載入 `.so`，走 C 高速路徑。
- **Windows Python**：載入失敗，自動退回標準庫 `urllib`，功能不中斷。

### 情境 C：進階用法（curl.py 提供的三個層級 API）

| 函式 | 回傳 | 適合場景 |
|------|------|----------|
| `fetch(url)` | `{status_code, body, url, success, error?}` | 需要知道狀態碼 + 內容 |
| `fetch_text(url)` | body 字串或 None | 只要純文字內容 |
| `fetch_json(url)` | 解析後的 dict/list 或 None | 拿 API 的 JSON |

## 5. 端到端資料流（一次請求的完整旅程）

以 `fetch("https://httpbin.org/get")` 為例：

```
 Python                  C 層                               網路
─────────          ──────────────                      ─────────
fetch(url)
   │
MiniCurl.get()
   │  url.encode('utf-8')              （字串 → bytes）
   ├─────────►  http_get(url, &code)
   │                │
   │                ├─ 解析 host= httpbin.org, path= /get, port= 443
   │                ├─ getaddrinfo() ──────────► DNS 查詢
   │                ├─ socket() + connect() ───► TCP 三次交握
   │                ├─ SSL 交握 + 憑證驗證 ◄──── TLS handshake
   │                ├─ ssl_send_all(GET 請求) ─► 送出加密 HTTP request
   │                ├─ SSL_read() 迴圈 ◄──────── 收解密後 HTTP response
   │                ├─ 抽出 status = 200
   │                ├─ 切出 body
   │                └─ 回傳 body 指標
   │  c_char_p 回傳（bytes）
   │  code.value = 200
   ├─────────►  body.decode('utf-8')
   │
   └─►  {status_code:200, body:"...", success:True}
```

記憶體協定（重要）：

| 邊界 | 誰配置 | 誰釋放 |
|------|--------|--------|
| C 內部 `ResponseBuffer` | `malloc/realloc` | C 內部（req fail 時 reachable） |
| `http_get` 回傳的 body | `malloc`（buffer.data） | **Python ctypes**（自動）／C 呼叫端（`free()`） |

## 6. 測試流程

### C 測試

```
1. 編譯（tests/test_curl.c 直接 #include "../src/curl.c"，把源碼編進來）
     gcc -o build/test_curl tests/test_curl.c -lssl -lcrypto
2. 執行
     ./build/test_curl
```

涵蓋 6 個案例：

| 測試 | 預期 |
|------|------|
| `GET /get` | status 200、body 非空 |
| `GET /status/404` | status 404 |
| `GET doesnotexist.invalid` | 連線失敗 → 回傳 NULL |
| `HTTPS GET https://httpbin.org/get` | status 200、body 非空 |

每失敗一個案例就 `exit(1)`，全過印 `6 tests passed`。

### Python 測試

```bash
python3 tests/test_curl.py
```

不用 pytest 也能跑（`__main__` 區塊會逐一執行 `test_*` 函式）。涵蓋：

- 正常請求（200）
- 404（驗證空 body 也算成功，不會誤判）
- 無效網域（success=False）
- `fetch_text` / `fetch_json` 行為

## 7. 常見執行路徑速查

| 想做的事 | 指令 |
|----------|------|
| 完整建置 | `./build.sh` |
| 跑 C 可執行檔 | `./build/curl <URL>` |
| 跑 C 測試 | `gcc -o build/test_curl tests/test_curl.c -lssl -lcrypto && ./build/test_curl` |
| 跑 Python 測試 | `python3 tests/test_curl.py` |
| 用 Python 抓網頁 | `python3 src/curl.py <URL>` |
| 在 Windows 用 Python | 直接 `python src/curl.py <URL>`（自動退到 urllib） |

## 8. 依賴與環境

| 項目 | 需求 | 備註 |
|------|------|------|
| 建置 | `gcc`、POSIX socket（Linux/WSL/macOS） | 不需 libcurl |
| HTTPS | **OpenSSL 開發套件**（`libssl-dev` / `openssl-devel`） | C 版本 HTTPS 的必要依賴 |
| Python | Python 3.6+（標準庫） | ctypes 為內建；無網時 urllib 超時 |
| 網路 | 可連外網（測試用 httpbin.org） | |
| Windows | 不需編譯，curl.py 自動用 urllib | C 函式庫需在 WSL 內使用 |

---

## 9. 改動流程（團隊協作範例）

1. 改 `src/curl.c` → `./build.sh` 重編 → `python3 tests/test_curl.py` 驗證。
2. 改 `src/curl.py` → 直接 `python3 src/curl.py <URL>` 測試。
3. 新增測試案例 → 掛到 `tests/test_curl.py`（`test_` 開頭即自動被發現）。
4. 心法：**C 動過一定重跑 C 測試，Python 層動過跑 Python 測試，跨層動過兩個都跑。**

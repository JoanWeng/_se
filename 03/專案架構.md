# 遊戲引擎基礎架構筆記

> 狀態:規劃階段,尚待確認後從 M1 開始實作。

## 一、技術選型(預設假設)

| 項目 | 選擇 | 理由 |
|---|---|---|
| 語言 | C++20 | 業界主流,效能可控 |
| 建置 | CMake | 跨平台 |
| 視窗/輸入 | GLFW 3.4 | 輕量 |
| 圖形 API | OpenGL 4.5 | 入門門檻低,經 RHI 可換 Vulkan |
| 維度 | 2D 優先,保留 3D 擴充 | 最快跑出成果 |
| ECS | EnTT | 解耦且效能好 |
| 平台 | Windows / Linux / macOS | |

## 二、專案檔案架構

```
engine/
├─ CMakeLists.txt              # 頂層:C++20、輸出目錄
├─ cmake/                      # 編譯警告、第三方設定
├─ engine/
│  ├─ CMakeLists.txt           # 靜態函式庫 target: Engine
│  ├─ include/engine/          # 對外公開標頭
│  └─ src/
│     ├─ core/                 # Log, Assert, Timer, Types, UUID
│     ├─ platform/             # Window, Input, FileSystem
│     ├─ events/               # Event, EventDispatcher
│     ├─ resource/             # Handle, ResourceCache
│     ├─ renderer/
│     │  ├─ rhi/               # 抽象介面
│     │  ├─ opengl/            # OpenGL 後端
│     │  └─ 2d/                # Batch Renderer, Camera
│     ├─ scene/                # Scene, Entity, Components, Systems
│     └─ application/          # Application, Layer, LayerStack
├─ sandbox/                    # 執行檔 target: Sandbox
├─ assets/                     # shaders/ textures/ ...
└─ third_party/                # glad, stb_image 等
```

- 公開標頭與內部實作分離,Sandbox 只能 include `engine/` 下的標頭。
- 新增 Vulkan 只需加 `renderer/vulkan/`。
- 編譯選項:`-Wall -Wextra`(MSVC `/W4`),Debug 開啟 AddressSanitizer。

## 三、設計原則

1. **單向依賴**:上層依賴下層,下層不知道上層存在。
2. **抽象只放在會換的地方**:Renderer(RHI)與 Window 需要抽象,其餘用具體類別。
3. **資料與邏輯分離**:Component 只存資料,System 只處理邏輯。
4. **所有權明確**:獨佔用 `unique_ptr`,共享資源用 Handle,不用裸 `new/delete`。
5. **先正確再優化**:瓶頸等 profiling 後處理。

## 四、模組分層

```
Application(遊戲專案)
   ↓
Scene / ECS ── Scripting(後期)
   ↓
Renderer ── Audio ── Physics(後期)
   ↓
Resource ── Event
   ↓
Platform(視窗、輸入、檔案)
   ↓
Core(Log、Time、Memory、Assert、Math)
```

## 五、模組詳細設計

### Core

| 元件 | 說明 |
|---|---|
| `Log` | 包裝 spdlog,Engine / App 兩個 logger,Trace~Critical |
| `Assert` | `ENGINE_ASSERT(cond, msg)`,Debug 中斷,Release 可關閉 |
| `Timer` | `steady_clock`,提供 deltaTime、總時間 |
| `Types` | `Ref<T>`、`Scope<T>`、固定寬度整數別名 |
| `UUID` | 64-bit 隨機 ID |
| `Math` | 直接使用 GLM,附 Transform 輔助函式 |

### Platform

```cpp
class Window {
    virtual void PollEvents() = 0;
    virtual void SwapBuffers() = 0;
    virtual uint32_t Width() const = 0;
    virtual uint32_t Height() const = 0;
    virtual void SetEventCallback(EventCallback) = 0;
    virtual void* NativeHandle() const = 0;
    static Scope<Window> Create(const WindowDesc&);
};

class Input {
    static bool IsKeyDown(KeyCode);
    static bool IsMouseDown(MouseButton);
    static glm::vec2 MousePosition();
};
```

- `GlfwWindow` 為唯一實作;Input 為靜態查詢介面。
- `FileSystem`:讀取文字/二進位檔、assets 根目錄路徑解析。

### Event

- 基底 `Event`:型別列舉 + 分類旗標 + `handled` 標記。
- 種類:WindowClose / WindowResize / KeyPressed / KeyReleased / MouseMoved / MouseButtonPressed / MouseScrolled。
- `EventDispatcher::Dispatch<T>(handler)` 依型別分派。
- 傳遞順序:Window callback → Application → Layer(**由上而下**,`handled` 後停止)。

### Resource

```cpp
template<typename T> class Handle { uint32_t index, generation; };

template<typename T> class ResourceCache {
    Handle<T> Load(const std::string& path);
    T* Get(Handle<T>);
    void Release(Handle<T>);
};
```

- Handle 帶 generation,避免懸空參照。
- 以路徑為 key 快取,重複載入回傳同一 Handle。
- 類型:Texture、Shader,後期加 Sound、Font。
- 流程:`path → FileSystem → 解碼 → 建立 GPU 資源`;先同步,保留改非同步的空間。

### Renderer

**RHI 抽象層(OpenGL 為第一個後端)**

| 介面 | 職責 |
|---|---|
| `GraphicsContext` | 初始化 GL、載入函式 |
| `VertexBuffer` / `IndexBuffer` | 頂點與索引資料 |
| `VertexArray` | 頂點佈局 `BufferLayout` |
| `Shader` | 編譯、連結、設定 uniform |
| `Texture2D` | 建立、綁定 slot、參數 |
| `Framebuffer` | 離屏渲染(後期) |
| `RenderCommand` | `Clear`、`SetViewport`、`DrawIndexed` |

**2D Renderer**

- 流程:`BeginScene(camera)` → `DrawQuad/DrawSprite` → `EndScene()`。
- 批次:單一動態頂點緩衝,每 Quad 4 頂點,索引緩衝預先生成;達 10,000 quad 或 16 個紋理 slot 滿才 flush。
- 頂點格式:`position, color, texCoord, texIndex, tilingFactor`。
- 統計:Draw call 數、Quad 數。

**Camera**

- `OrthographicCamera`:位置、旋轉、縮放、投影矩陣。
- `CameraController`:處理 resize 與縮放。
- 3D 時加 `PerspectiveCamera`,共用只存投影矩陣的 `Camera` 基底。

### Scene / ECS

- `Scene` 持有 `entt::registry`,提供 `CreateEntity(name)`、`DestroyEntity`。
- `Entity` 為輕量包裝(entity handle + scene 指標):`AddComponent<T>`、`GetComponent<T>`、`HasComponent<T>`。

| Component | 內容 |
|---|---|
| `Tag` | 名稱 |
| `ID` | UUID |
| `Transform` | position、rotation、scale |
| `SpriteRenderer` | color、texture handle、tiling |
| `CameraComponent` | camera、primary 旗標 |

- System:`TransformSystem`、`SpriteRenderSystem`、`CameraSystem`。
- 階層(Parent/Child)與場景序列化(JSON)放後期。

### Application

- `Application`:持有 Window、LayerStack、Timer,管理主迴圈。
- `Layer`:`OnAttach / OnDetach / OnUpdate(dt) / OnFixedUpdate(dt) / OnRender / OnEvent`。
- `LayerStack`:一般 Layer 在下,Overlay 永遠在上。
- 遊戲專案繼承 `Application`,由引擎 `main` 呼叫 `CreateApplication()`。

## 六、主迴圈

```
Init(Log → Window → Renderer → Layers)
accumulator = 0
while running:
    dt = timer.Tick()                  // 夾上限 0.25s,避免死亡螺旋
    window.PollEvents() → 事件由上而下分發
    accumulator += dt
    while accumulator >= fixedStep:    // 預設 1/60
        layers.OnFixedUpdate(fixedStep)
        accumulator -= fixedStep
    layers.OnUpdate(dt)
    alpha = accumulator / fixedStep
    Renderer.Begin
    layers.OnRender(alpha)             // alpha 供位置插值
    Renderer.End
    window.SwapBuffers()
Shutdown(逆序釋放)
```

- 固定步長邏輯 + 可變幀率渲染。
- 視窗最小化時暫停渲染,繼續處理事件。

## 七、執行緒與記憶體

- 初期單執行緒,所有 GL 呼叫在主執行緒。
- 預留資源載入 worker thread(背景解碼,主執行緒上傳 GPU)。
- 批次頂點緩衝為預先配置的固定陣列,避免每幀配置。

## 八、開發里程碑

| 里程碑 | 內容 | 驗收標準 |
|---|---|---|
| **M1 骨架** | CMake、Types、Log、Assert、Timer、GlfwWindow、空迴圈 | 開出視窗可關閉,log 正常,無洩漏 |
| **M2 事件與輸入** | Event、Layer/LayerStack、Input | 鍵鼠事件傳到 Layer,`handled` 可攔截 |
| **M3 渲染基礎** | GraphicsContext、Buffer、VertexArray、Shader、Texture、RenderCommand | 畫出帶紋理的四邊形 |
| **M4 2D 渲染** | Batch Renderer、OrthographicCamera、CameraController | 10,000 Sprite,draw call 個位數,可平移縮放 |
| **M5 ECS 場景** | Scene、Entity、Components、Systems | 以 Entity 建立多個 Sprite,Transform 移動 |
| **M6 資產管理** | Handle、ResourceCache、Shader/Texture 載入 | 重複載入同貼圖只建立一次,釋放後 Handle 失效 |

每個里程碑結束時 Sandbox 都有可執行展示。

## 九、編碼規範

- 命名:類別/函式 `PascalCase`、成員 `m_` 前綴、常數 `kPascalCase`。
- 程式碼精簡,不放多餘 print 與冗長註解,僅在非顯而易見處留簡短註解。
- 修改既有檔案時只列出變動部分,不貼完整檔案。

# 05 專案架構規劃書（待確認，未實作）

## 一、需求回顧

- 繳交內容：`Dockerfile` + `docker-compose.yml`
- 微服務：nginx（web server + reverse proxy）、PostgreSQL（資料庫）
- 開發執行環境：Node.js、Rust、Python（可選）
- 簡易 web 介面展示系統

## 二、擬定架構

```
Browser ── :8080 ──▶ nginx（serve 展示頁＋反向代理）
  ├─ /             → 靜態前端
  ├─ /api/node/    → api-node:3000   （Node.js 20 + Express）
  ├─ /api/python/  → api-python:5000  （Python 3.11 + Flask）
  └─ /api/rust/    → api-rust:8000    （Rust + Axum）
        三後端共用 → db:5432（PostgreSQL 16，visits 表）
```

- 容器 5 個，全掛自訂 bridge 網路 `app-net`，服務名互連
- 只有 nginx 對外開 `8080:80`；DB 與後端只走內網
- 後端等 DB healthy 才啟動（`depends_on + pg_isready`）；DB 資料用 named volume `pgdata` 持久化
- Rust 用 multi-stage build（`rust:bookworm` 編譯 → `debian:bookworm-slim` 跑，避免舊 Cargo 不支援 edition2024 的問題——前一版在此踩過坑）

## 三、擬定檔案結構

```

  backend-rust/Dockerfile + Cargo.toml + src/main.rs

```

## 四、擬定 API（每支後端相同語義，方便展示頁統一呼叫）

| 端點 | 行為 |
|---|---|
| `GET /` | 回服務名＋runtime 問候（不碰 DB） |
| `GET /health` | `SELECT 1` 驗 DB，ok / error 皆回 JSON 不 crash |
| `GET /api/users` | 寫入一筆 visits 再回最新 5 筆，證明 DB 讀寫正常 |

展示頁經由 `/api/<svc>/...` 打 nginx，由其剝前綴轉發。

## 五、驗收方式

```bash
docker compose up --build -d
docker compose ps                    # 5 個 Up，db 為 healthy
curl localhost:8080/api/node/health  # python、rust 同理
# 瀏覽器開 http://localhost:8080，全卡片 OK＋讀得到 DB
docker compose down                  # 結束；down -v 連 DB 全清
```

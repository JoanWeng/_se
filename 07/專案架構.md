## 1. 緣起與目標

- 目標 1：將網站部署到 Cloudflare，取得正式網址與可持續更新的部署流程。
- 目標 2：網站內容為「留言板」，支援免註冊留言與基本管理功能。

### 非功能需求

## 3. 技術選型決策

### 3.1 部署方案決策矩陣

| 網站類型 | 建議方案 | 說明 |
| --- | --- | --- |
| 純靜態網站（HTML/CSS/JS） | Cloudflare Pages | 直接上傳或 Git 整合 |
| 前端框架（React / Vite / Astro…） | Cloudflare Pages | 自動偵測框架出 build 產物 |
| **全端 / SSR / API（本專案）** | **Cloudflare Workers** ✅ | Hono + D1，一個 Worker 完成前後端 |
| 只有 API / 後端服務 | Cloudflare Workers | `wrangler deploy` |

> 本專案選擇 **Workers 而非 Pages**：留言板需要後端 API 與資料庫，Cloudflare 目前也建議新專案直接用 Workers（Static Assets 已內建），單一 Worker 同時服務網頁與 API，架構最簡。

### 3.2 技術選型

| 層 | 選擇 | 理由 |
| --- | --- | --- |
| 前端 | 純 HTML + CSS + Vanilla JS（無框架、無 build） | 留言板規模小，零 build 最單純 |
| 後端 API | Cloudflare Workers + **Hono** | 輕量路由框架，跑在 Cloudflare 邊緣 |
| 資料庫 | **Cloudflare D1**（SQLite） | 與 Workers 原生整合、免費額度足夠 |
| 本地工具 | **Deno**（跑 `npm:wrangler`） | 機器環境以 Deno 為主,Deno 2 可執行 wrangler 與 TS |
| 部署 | `wrangler deploy` | 靜態檔與 API 一次部署 |

## 4. 系統架構與流程

```
瀏覽器
   │  HTTPS（自動 Universal SSL）
   ▼
Cloudflare 邊緣網路（內建 DDoS 保護）
   │
   ▼
Cloudflare Worker「se07-guestbook」
   ├─ GET /、/joan.html        → public/ 靜態資產（Workers Static Assets）
   ├─ GET/POST/DELETE /api/messages*    → Hono 路由
   └─ POST/GET/DELETE /api/admin/*      → Hono 路由 + token 驗證
   │
   ▼ D1 binding (env.DB)
Cloudflare D1「guestbook」
   ├─ messages         留言（密碼為 SHA-256 hash、發文 IP）
   ├─ banned           封鎖名單
   └─ admin_attempts   管理登入失敗記錄（速率限制）
```

### 4.1 留言流程
1. `index.html` 表單（暱稱/留言/刪除密碼）→ `app.js` 打 `POST /api/messages`
2. Worker：封鎖 IP 檢查（403）→ 速率限制（429）→ 欄位驗證（400）
3. 密碼 SHA-256 雜湊後連同發文 IP 寫入 `messages`
4. 前端重抓列表，以 textContent 渲染留言

### 4.2 留言刪除流程
- 使用者：點刪除 → 輸入當時密碼 → `DELETE /api/messages/:id` → 驗對 hash → 204 / 403
- 管理者：後台 `DELETE /api/admin/messages/:id`（token 驗證，免留言密碼）

### 4.3 管理後台流程
1. `POST /api/admin/login`：密碼比對（密碼存放於 Cloudflare Secret），失敗記錄至 `admin_attempts`；15 分鐘內失敗 ≥ 10 次鎖 429
2. 登入成功發放 token = `過期時間戳 + HMAC-SHA256 簽章`（8 小時有效）
3. admin API 皆驗 `Authorization: Bearer` 重算 HMAC 驗簽
4. token 存 `sessionStorage`（關分頁即失效）

## 5. 資料模型（schema.sql 實際內容）

```sql
CREATE TABLE messages (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT    NOT NULL,
  content     TEXT    NOT NULL,
  password    TEXT    NOT NULL,   -- SHA-256 雜湊
  ip          TEXT    NOT NULL,
  created_at  TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE banned (
  ip          TEXT    PRIMARY KEY,
  reason      TEXT    NOT NULL DEFAULT '',
  created_at  TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE admin_attempts (
  ip          TEXT    NOT NULL,
  created_at  TEXT    NOT NULL DEFAULT (datetime('now'))
);
```

欄位限制：`name` ≤ 20 字、`content` ≤ 500 字、`password` 4–64 字（前後端雙重驗證）。

### 編號行為
- 前台顯示的「N 樓」是依時間排序**動態計算的樓層**（`total - (page-1)×20 - 位置`），最上面永遠是最新留言
- `id` 是資料庫的自動遞增主鍵（僅內部用於刪除定位）：留言刪除後該 ID **永久空號且不會重新被使用**（SQLite `AUTOINCREMENT` 特性），新留言一律使用比歷史最大值更大的新 ID

## 6. API 總表

### 公開

| Method | 路徑 | 說明 |
| --- | --- | --- |
| GET | `/api/messages?page=N` | 列表 `{items, page, maxPage, total}` |
| POST | `/api/messages` | 新增 `{name, content, password}` → `201 {id}` |
| DELETE | `/api/messages/:id` | body `{password}` → `204` / `403` |

### 管理（Bearer token）

| Method | 路徑 | 說明 |
| --- | --- | --- |
| POST | `/api/admin/login` | `{password}` → `{token}` |
| GET | `/api/admin/messages?page=N` | 列表含 `ip` |
| DELETE | `/api/admin/messages/:id` | 免留言密碼刪除 |
| GET | `/api/admin/banned` | 封鎖名單 |
| POST | `/api/admin/ban` | `{ip, reason}` 封鎖（重複封鎖自動跳過） |
| DELETE | `/api/admin/ban/:ip` | 解除封鎖 |

錯誤格式統一 `{error: "..."}`：400 欄位無效 / 401 未登入 / 403 密碼錯或被封鎖 / 404 不存在 / 429 速率限制。

## 8. 安全性設計

| 風險 | 對策 | 狀態 |
| --- | --- | --- |
| XSS | `textContent` 純文字渲染、不使用 innerHTML、送出前 trim | ✅ |
| SQL injection | prepared statement（`.bind()`） | ✅ |
| SQL 密碼安全 | SHA-256 雜湊（`crypto.subtle`），不存明文 | ✅ |
| 垃圾留言 | 同 IP 5 分鐘最多 5 則（D1 計數）；換 IP 攻擊仍可能繞過 | ✅（有限） |
| 管理後台 | 密碼存 Cloudflare Secret；HMAC token 8 小時；登入失敗 10 次/15 分鐘鎖 429 | ✅ |
| CORS | 同一 Worker 同源，不開放跨域 | ✅ |
| 機密外洩 | `.dev.vars` 在 `.gitignore`；密碼不出現在任何程式碼 / 文件 | ✅ |

## 12. 風險與注意事項

1. **測試污染正式環境**：管理登入失敗次數表曾造成管理者自己被鎖（測試腳本在正式環境連打錯誤密碼），已清空紀錄並將該測試改成僅本地執行
2. **資料可復原性**：留言資料尚無自動備份，需手動 `wrangler d1 export`
3. **DNS 生效時間**：改 nameserver 最多可能需 24 小時（若加自訂網域）
4. **快取**：Workers 回應不快取；靜態資產有完整性保護
5. **免費額度**：Workers 每日 100k 請求、D1 每日 5M 讀 / 100k 寫、5GB 統一容量
6. **帳號安全**：最重要的單點是 Cloudflare 帳號（可刪 DB & Worker），建議啟用 2FA
7. **網址續存條件**：`workers.dev` 子網域只要 Cloudflare 帳號存在就有效

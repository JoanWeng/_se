# 套件發佈專案架構（JSR）

> 日期：2026-11-13 狀態：規劃中 基底：`07/` 的留言板後端（Hono + Cloudflare D1）
> 目標：把 07 的留言板後端抽成可重用的套件，發佈到
> **JSR**（jsr.io）公開讓任何人安裝。 修改範圍：僅限本目錄（`08/`）；`07/`
> 只讀不改。

---

## 1. 緣起與目標

- 07 已上線的留言板 Worker，其後端邏輯（留言 CRUD、速率限制、IP 封鎖、管理
  token）是通用能力，任何人做 Cloudflare 留言板都需要同一套
- 把它抽成一個套件：使用者在自己的 Worker 中一行建立整個留言板
  API，再自己掛上前端頁面
- 發佈到 JSR：`deno publish` 即可，不需要安裝 Node.js/npm

### 非目標

- 不重寫 07 的專案；07 保持原樣（本套件由 07 的程式「移植」而來）
- 不包含前端頁面（`public/`）：前端留給使用者自己客製；README 說明如何沿用 07
  式前端

### 公開 API

```ts
// 1. 建立整個留言板 app（公開 + 管理 API，路徑與 07 完全相同）
export function createGuestbookApp(
  options?: GuestbookOptions,
): Hono<GuestbookEnv>;

// 2. 資料表 schema（可直接餵給 wrangler d1 execute）
export const SCHEMA_SQL: string;

// 3. 預設選項（閱讀用）
export const DEFAULT_OPTIONS: Required<GuestbookOptions>;
```

`GuestbookOptions`（全部有預設值，與 07 行為一致）：

| 選項                                            | 預設     | 說明               |
| ----------------------------------------------- | -------- | ------------------ |
| `pageSize`                                      | 20       | 每頁留言數         |
| `nameMax` / `contentMax`                        | 20 / 500 | 暱稱、內容長度上限 |
| `passwordMin` / `passwordMax`                   | 4 / 64   | 刪除密碼長度範圍   |
| `rateLimitWindowMinutes` / `rateLimitMax`       | 5 / 5    | 留言速率限制       |
| `adminAttemptWindowMinutes` / `adminAttemptMax` | 15 / 10  | 管理登入失敗鎖定   |
| `tokenTtlMs`                                    | 8 小時   | 管理 token 有效期  |

環境綁定（與 07 相同）：`Bindings` 需要
`DB: D1Database`、`ADMIN_PASSWORD: string`。

## 3. 系統架構

```
使用者的 Worker（src/index.ts）
   │
   │  export default createGuestbookApp({ ... })
   ▼
本套件（@nqucsie111310512/message-board）
   ├─ 公開 API：GET/POST/DELETE /api/messages*
   │    欄位驗證 → IP 封鎖檢查 → 速率限制 → SHA-256 密碼雜湊 → 寫入
   ├─ 管理 API：/api/admin/login、/api/admin/messages、/api/admin/ban*
   │    失敗計數鎖定 → HMAC token（Bearer 驗簽）
   ▼ D1 binding (env.DB)
使用者的 Cloudflare D1
   ├─ messages / banned / admin_attempts（SCHEMA_SQL 建表）
```

使用方式（README 會示範的完整 Worker）：

```ts
// src/index.ts（使用者專案）
import { createGuestbookApp } from "jsr:@nqucsie111310512/message-board@1";

export default createGuestbookApp();
// 或自訂限制：
// export default createGuestbookApp({ pageSize: 50, rateLimitMax: 3 });
```

靜態頁面使用者可用 Workers Static Assets 掛自己的 `public/`（沿用 07
的前端只需把 fetch 路徑對準 `/api/*`，完全相容）。

## 4. 目錄結構（08/ 實際）

```

├── jsr.json               # 套件設定：scope/name、version、exports、publish 內容

│   ├── mod.ts             # 對外入口：re-export + options 預設值

│   ├── options.ts         # GuestbookOptions 型別 + DEFAULT_OPTIONS
│   └── types.ts           # 最小 D1Database / D1PreparedStatement / Env 型別

├── test/
│   ├── mock_d1.ts         # 純 JS 模擬 D1Database（支援本套件用到的 SQL）
│   └── app_test.ts        # Deno.test：對照 07 的 13 項公開測試 + 管理區測試

├── LICENSE                # MIT
└── 專案架構.md             # 本文件
```

移植對照：`07/src/index.ts`（單檔 312 行）拆成 `app.ts` + `crypto.ts` +
`options.ts`，行為不變；路由、錯誤格式、SQL 全部照抄，僅把常數改成可設定。

## 5. 實作流程

| 步驟        | 內容                                                                              | 驗收                                |
| ----------- | --------------------------------------------------------------------------------- | ----------------------------------- |
| 1. 前置     | 到 jsr.io 確認帳號與 scope（§7）                                                  | 知道最終套件名                      |
| 2. 腳手架   | `jsr.json`、`deno.json`、LICENSE、schema.sql                                      | `deno publish --dry-run` 能讀到設定 |
| 3. 移植     | `types.ts`、`crypto.ts`、`options.ts`、`app.ts`、`mod.ts`                         | `deno check` 通過                   |
| 4. 測試     | `mock_d1.ts` + `app_test.ts`（公開 13 項 + 管理區）                               | `deno test` 全綠                    |
| 5. 文件     | `README.md`、公開 API 補 JSDoc（JSR 文件分數）                                    | JSR 快速檢查通過                    |
| 6. 發佈演練 | `deno publish --dry-run --allow-dirty`                                            | 無錯誤、內容清單正確                |
| 7. 發佈     | `deno publish`（在 PowerShell 執行，互動登入）                                    | jsr.io 出現版本頁                   |
| 8. 驗證     | 另開一個暫存專案 `deno add jsr:@nqucsie111310512/message-board` 安裝並 smoke test | 能 import、能建 app                 |

## 6. 測試計畫（對照 07）

`test/app_test.ts` 用 mock D1（記憶體實作
`prepare().bind().first()/run()`，支援本套件用到的 SELECT/INSERT/DELETE/COUNT
語法）直接呼叫 Hono app 的 `app.request()`，不需要網路：

- 公開區（對照 `07/test.ps1`）：列表分頁與樓層總數、新增成功 201、欄位驗證
  400（名稱/內容/密碼長度）、速率限制 429、刪除正/錯密碼 204/403、不存在
  404、重複留言 id 不重用
- 管理區（對照 `07/test_admin.ps1`）：登入錯密碼 401、token 發放與驗證、無 token
  401、管理刪除免密碼、封鎖後留言 403、封鎖名單增刪、連續登入失敗鎖定
  429（測試用小參數）

`schema.sql` 另以字串斷言核對與 07 相同。

## 8. 風險與注意

| 風險                                                              | 對策                                                            |
| ----------------------------------------------------------------- | --------------------------------------------------------------- |
| JSR 要求 scope 存在且由本人擁有                                   | 發佈前先在 jsr.io 建立 scope；`deno publish` 互動登入綁定帳號   |
| 移植行為走樣                                                      | 路由/SQL 照抄 07 + 測試對照 07 的腳本逐項覆寫                   |
| mock D1 與真 D1 行為差異（如 `datetime('now')`、`AUTOINCREMENT`） | mock 內實作該子集並註明；上線煙霧測試（步驟 8）在真環境驗證一次 |
| JSR slow-types 檢查                                               | 公開 API 全部顯式型別，不用 `satisfies` 推斷陷阱                |
| 版本不可覆蓋                                                      | JSR 發佈後版本不可改，先 `--dry-run` 確認再發                   |
| 套件名衝突                                                        | JSR scope 內唯一，衝突即代表重發，換版本即可                    |
